# Альтернативное размещение: VPS / Node.js / Docker

[Открыть текущий тестовый сайт](https://droptoptri.github.io/physics/) · [Исходный код](https://github.com/droptoptri/physics/tree/main)

Домен можно оставить на REG.RU. Готовая серверная версия включает сайт, регистрацию и подтверждение партнёров, закрытые тендеры, приём анкет и очередь писем на **antnpk@gmail.com**. GitHub Pages показывает только демонстрацию интерфейса.

Домен пользователя: **sgt-h.ru**. Тариф хостинга пока не указан; применимость VPS-инструкции к купленной услуге ещё нужно подтвердить.

## 1. Сначала проверьте купленный хостинг

В личном кабинете REG.RU откройте услугу хостинга и посмотрите **точное название тарифа**, затем сообщите его вместе с доменом разработчику. Сам факт покупки хостинга ещё не подтверждает поддержку этого приложения.

Администратору или поддержке можно отправить такой вопрос:

> Можно ли на моём тарифе постоянно запускать Node.js 24+ / Express, использовать встроенный модуль node:sqlite, хранить базу и загруженные документы на постоянном диске и направлять HTTPS-запросы к процессу Node? Есть ли доступ к Docker Compose либо возможность настроить обратный прокси?

Если доступен только файловый менеджер, FTP и PHP/MySQL, **эта серверная версия там не запустится**. Одна загрузка папки `dist` не включит кабинет и отправку анкет. Потребуется VPS/облачный сервер либо отдельная адаптация backend под возможности тарифа. Сначала уточните тариф; покупать дополнительную услугу вслепую не нужно.

Дальнейшие шаги описывают подготовленный и проверенный вариант **для VPS с Ubuntu 24.04 и Docker Compose**. Если ваш тариф поддерживает Node.js без Docker, администратор может использовать [инструкцию прямого запуска](DEPLOYMENT.md).

## 2. Что нужно для VPS-варианта

- Сервер с публичным IPv4, Ubuntu 24.04, SSH-доступом. Практический начальный размер: 2 vCPU, 2 ГБ RAM, 20 ГБ SSD; размер диска зависит от количества анкет. Для хранения персональных данных российских пользователей выбирайте подходящее размещение, например ЦОД в РФ.
- Купленный основной домен **`sgt-h.ru`**. Все DNS-записи и команды ниже уже указаны для него. Для кириллического домена используйте его Punycode-имя из панели регистратора.
- Действующий контактный email для уведомлений о HTTPS-сертификате.
- Параметры SMTP от вашего почтового провайдера: сервер, порт, логин, пароль приложения и разрешённый отправитель. Получатель анкет уже задан: `antnpk@gmail.com`; он не обязан совпадать с отправителем.

Сервер необязательно покупать у регистратора домена. Уже оплаченный обычный хостинг не является VPS; перед изменением услуги уточните варианты у поддержки.

## 3. Направьте sgt-h.ru на сервер

В REG.RU откройте домен `sgt-h.ru` → управление DNS / ресурсными записями. Названия пунктов могут отличаться. Если у домена указаны DNS другого провайдера, редактируйте записи у него. Не меняйте NS вслепую: это может затронуть действующую почту.

Создайте или измените только веб-записи:

| Тип | Имя / поддомен | Значение |
| --- | --- | --- |
| A | `@` (основной домен) | Публичный IPv4 вашего VPS |
| CNAME | `www` | `sgt-h.ru.` |
| A | `cons` | Тот же публичный IPv4 VPS |

Для `www` также допустима A-запись на тот же IP вместо CNAME. Одновременно создавать оба типа для одного имени не нужно. Удалите конфликтующие старые A/CNAME для этих имён. Если IPv6 на VPS не настроен, удалите старые AAAA **только у этих веб-имён**. Существующие MX, SPF/DKIM/DMARC, TXT и другие записи почты сохраните.

Результат:

- `https://sgt-h.ru` — лендинг;
- `https://www.sgt-h.ru` — переход на основной домен;
- `https://cons.sgt-h.ru` — сразу раздел СГТ-КСК;
- `https://sgt-h.ru/cabinet` — кабинет партнёра.

Дождитесь обновления DNS. Обычно это занимает от нескольких минут до суток, иногда до 48 часов. На компьютере можно проверить `nslookup sgt-h.ru` и `nslookup cons.sgt-h.ru`: ответ должен содержать IP вашего VPS. Все три имени должны указывать на сервер, чтобы для каждого выпустился сертификат.

## 4. Подключитесь к серверу и установите Docker

Следующие команды выполняются **в SSH-терминале VPS**, а не в чате, не в настройках Codex и не в файловом менеджере REG.RU. Администратор может выполнить весь этот раздел за вас.

В Windows откройте PowerShell, в macOS — Terminal. Замените `SERVER_IP` реальным IP:

```sh
ssh root@SERVER_IP
```

Перед подтверждением первого подключения сверьте SSH-отпечаток с данными сервера/администратора. Войдите способом, выданным REG.RU. Пароль при вводе в терминале не отображается; в переписку его присылать не нужно.

Дальше команды предполагают вход под `root` на **новый Ubuntu 24.04 VPS**. При входе обычным пользователем администратор применяет `sudo` там, где нужны права системы.

```sh
apt-get update
apt-get install -y docker.io docker-compose-v2 git ca-certificates
systemctl enable --now docker
docker version
docker compose version
```

В сетевом экране провайдера разрешите входящие TCP 80 и 443, SSH на настроенном порту (обычно 22). UDP 443 нужен для HTTP/3, но необязателен для работы сайта. Порт приложения 3000 наружу открывать не нужно. Если есть системный firewall, администратор должен проверить и его правила. На сервере не должны занимать 80/443 другой nginx/Apache/Caddy; существующий сайт сначала нужно учесть в плане переноса.

## 5. Скачайте сайт и создайте настройки

```sh
git clone --branch main --single-branch https://github.com/droptoptri/physics.git /opt/sgt
cd /opt/sgt
```

Домен `sgt-h.ru` уже подставлен. Замените только `admin@example.com` вашим действующим email:

```sh
docker run --rm --user "$(id -u):$(id -g)" \
  -v "$PWD:/work" -w /work node:24-bookworm-slim \
  node scripts/configure-production.mjs sgt-h.ru admin@example.com
```

Команда создаст закрытый `.env.production`, задаст разрешённые HTTPS-адреса и сгенерирует секрет сессий. Повторный запуск **не перезапишет** существующий файл. Секрет не нужно придумывать, копировать в чат или менять при каждом обновлении.

## 6. Подключите отправку анкет на почту

На сервере откройте конфигурацию:

```sh
nano .env.production
```

Заполните параметры, полученные от вашего почтового провайдера:

```dotenv
SMTP_HOST='smtp.provider.ru'
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER='forms@sgt-h.ru'
SMTP_PASS='пароль-приложения-из-почтового-сервиса'
SMTP_FROM='СГТ-Холдинг <forms@sgt-h.ru>'
```

Это пример структуры, а не рабочие реквизиты. Для порта 587 задайте `SMTP_SECURE=false`: соединение повышается до TLS через STARTTLS. Проверка сертификата остаётся включённой. Внешний SMTP-порт должен быть доступен с VPS; при блокировке обратитесь к провайдеру. Если отправитель на вашем домене, настройте SPF и DKIM по инструкции именно вашего почтового сервиса.

Если отправляете через Gmail, используйте `smtp.gmail.com`, параметры Gmail и пароль приложения, если он доступен для вашей учётной записи. Обычный пароль почты не следует использовать вместо пароля приложения. Отправка с Gmail-аккаунта требует разрешённого Gmail-отправителя, а не произвольного адреса на домене.

Сохраняйте значения пароля в одинарных кавычках, особенно если есть `$`, `#` или пробелы. Если пароль содержит одинарную кавычку, удобнее выпустить другой пароль приложения. Не запускайте `docker compose config` без `--quiet`: полный вывод содержит секреты.

В nano: `Ctrl+O`, Enter, затем `Ctrl+X`.

Без SMTP анкеты сохраняются в закрытой очереди, но **письма не приходят**. Сайт сообщает об этом; такая конфигурация годится для проверки, но не для обещания почтовой доставки партнёрам.

## 7. Запустите сайт

Всё ещё в `/opt/sgt`:

```sh
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production up -d --build --wait
docker compose --env-file .env.production ps
```

Первая сборка может занять несколько минут. Caddy автоматически выпускает и продлевает бесплатные HTTPS-сертификаты. Для этого должны правильно работать DNS, входящие порты 80/443 и исходящий доступ сервера к центру сертификации. Отдельно покупать SSL не требуется.

Проверьте с компьютера:

```sh
curl https://sgt-h.ru/api/health
curl -I https://cons.sgt-h.ru/
```

Первая команда должна вернуть `{"ok":true}`, вторая — перенаправление на `/ksk`. Затем откройте `https://sgt-h.ru` в обычном браузере: предупреждений о сертификате и баннера тестовой версии быть не должно. **Статус контейнера сам по себе не подтверждает, что DNS и сертификат уже работают.**

Если сайт недоступен:

```sh
cd /opt/sgt
docker compose --env-file .env.production ps
docker compose --env-file .env.production logs --tail=100 app web
```

Частые причины: DNS указывает на старый IP; осталась неверная AAAA; порт закрыт; 80/443 заняты; ошибся домен в `.env.production`; недостаточно памяти/диска. Сначала устраните причину, затем повторите запуск. Логи перед пересылкой проверьте на персональные данные и конфиденциальные сведения.

## 8. Проверьте рабочий сценарий перед приглашением партнёров

1. На телефоне проверьте КСК, ГЕО, меню и скачивание опросного листа.
2. Отправьте одну согласованную тестовую анкету через «Стать партнёром», без лишних персональных данных.
3. Убедитесь, что письмо **с вложением** пришло на `antnpk@gmail.com`; проверьте «Спам». Экран «принято» подтверждает сохранение заявки, а доставка проверяется отдельно.
4. Зарегистрируйте тестового партнёра: до подтверждения тендеры не должны показываться.
5. Подтвердите его на сервере командой ниже и проверьте вход после обновления страницы.
6. Добавьте настоящее предложение и проверьте доступ подтверждённого партнёра. В production нет демонстрационных аккаунтов и вымышленных предложений.
7. Уточните юридическое наименование и реквизиты оператора, сроки хранения и текст обработки данных в `/privacy` вместе с ответственным сотрудником до приёма реальных анкет. Текущий текст ещё не содержит полного набора реквизитов компании.

Просмотр пользователей и подтверждение (замените email):

```sh
docker compose --env-file .env.production exec -T app node scripts/admin.mjs users
docker compose --env-file .env.production exec -T app node scripts/admin.mjs approve partner@example.com
```

Проверка заявок и повторная отправка после настройки SMTP:

```sh
docker compose --env-file .env.production exec -T app node scripts/admin.mjs applications
docker compose --env-file .env.production exec -T app node scripts/admin.mjs retry-mail
```

Если SMTP-настройки менялись после запуска, сначала примените их:

```sh
docker compose --env-file .env.production up -d --wait
```

Сессии основного домена и `cons` раздельные: партнёр может войти на том адресе, с которого пользуется кабинетом.

## 9. Резервная копия и обновления

Из `/opt/sgt`:

```sh
bash scripts/backup-production.sh
```

Скрипт кратковременно останавливает приложение, сохраняет согласованную копию базы и анкет в `backups/`, затем запускает приложение. На время копирования посетители могут увидеть ошибку 502. Если копирование завершилось с ошибкой, скрипт пытается вернуть приложение в работу. Архив содержит закрытые данные: скачайте его на защищённое отдельное хранилище, ограничьте доступ и организуйте регулярное копирование. Копии только на том же VPS не защищают от потери сервера.

Отдельно защищённо сохраните `.env.production`. Он **не включён** в архив анкет. HTTPS-сертификаты хранятся в другом постоянном томе и при необходимости выпускаются повторно.

Обновление сайта:

```sh
cd /opt/sgt
bash scripts/backup-production.sh
git pull --ff-only origin main
docker compose --env-file .env.production up -d --build --wait
```

База, анкеты и очередь находятся в постоянном томе `sgt-holding_partner_data`. Обновление образа не удаляет этот том. **Не выполняйте `docker compose down -v`, `docker volume prune` и не удаляйте этот том**: это удалит анкеты и пользователей.

Для восстановления из **своей проверенной копии** администратор сначала сохраняет текущее состояние, останавливает `app`, распаковывает архив в отдельный новый том, проверяет владельца UID 1000 и целостность SQLite и переключает приложение на восстановленный том. Не распаковывайте непроверенный архив поверх действующей базы. Команда `tar -tzf backups/ИМЯ-АРХИВА.tar.gz` позволяет проверить состав копии без восстановления.

Публикация тендеров, отзыв доступа и удаление данных описаны в [руководстве администратора](DEPLOYMENT.md). В контейнере вместо `npm run admin -- …` используйте `docker compose --env-file .env.production exec -T app node scripts/admin.mjs …`; JSON-файл тендера сначала передайте в `/tmp` контейнера через `docker compose --env-file .env.production cp ПУТЬ-К-ФАЙЛУ app:/tmp/tender.json`.

## Что уже подготовлено, а что выполняется у вас

В репозитории есть production-сборка, `Dockerfile`, `compose.yaml`, HTTPS-прокси, генератор настроек, резервное копирование и проверки. Домен, DNS, покупки/смена тарифа и SMTP-учётная запись не менялись. Точный тариф и домен нужны, чтобы подтвердить применимость инструкции к вашей услуге. Внешняя доставка почты и публичный HTTPS вашего домена проверяются только после реального развёртывания.

Официальная справка REG.RU: [настройка ресурсных записей DNS](https://help.reg.ru/support/dns/nastroika-zony/), [размещение сайта на хостинге](https://help.reg.ru/support/hosting-i-servery/kak-razmestit-sayt-na-hostinge/).

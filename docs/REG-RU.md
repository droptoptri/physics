# Как разместить сайт на REG.RU: sgt-h.ru, тариф Хост-0

Подготовлена версия **PHP 8.3+ и MySQL для уже оплаченного Хост-0**. VPS и Node.js на вашем хостинге для неё не нужны. Сохраняются лендинг, кабинет, подтверждение партнёров, закрытые тендеры, приём анкет и очередь писем на **antnpk@gmail.com**.

[Тестовый просмотр дизайна](https://droptoptri.github.io/physics/) · [Готовый пакет sgt-host0.zip](https://github.com/droptoptri/physics/raw/refs/heads/main/releases/sgt-host0.zip)

GitHub Pages показывает демонстрацию интерфейса. Настоящие регистрации и анкеты работают после установки этого пакета на ваш хостинг. Доступа к вашему личному кабинету REG.RU у разработчика нет: следующие действия выполняете вы или ваш администратор. Пароли и коды подтверждения в чат присылать не нужно.

## 1. Откройте панель вашего хостинга

В REG.RU откройте **Мои услуги → Хостинг Хост-0 → управление / вход в панель управления**. Пункты могут называться немного иначе в разных версиях панели.

В панели найдите раздел сайтов / WWW-доменов. Для `sgt-h.ru` должен существовать отдельный сайт. Если его ещё нет — добавьте. Запишите **IP хостинга** и **корневую папку этого сайта** из его настроек. IP здесь берётся из карточки хостинга; выдумывать его или использовать IP GitHub Pages не нужно.

## 2. Подключите основной домен и поддомены

Добавьте `www.sgt-h.ru` и `cons.sgt-h.ru` как псевдонимы сайта либо отдельные WWW-домены, направленные **в ту же корневую папку, что sgt-h.ru**. Если для `cons` панель предлагает создать новую пустую папку, измените её на папку основного сайта.

В DNS домена создайте веб-записи:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `@` | IP вашего Хост-0 из панели REG.RU |
| CNAME | `www` | `sgt-h.ru.` |
| A | `cons` | Тот же IP Хост-0 |

Вместо CNAME для `www` можно использовать A на тот же IP. Одновременно оба типа не создавайте. Если уже есть старые A/CNAME для этих трёх имён, замените только их. Неверные AAAA у этих имён уберите, если IPv6 на хостинге не настроен. **MX и почтовые TXT, SPF/DKIM/DMARC сохраняйте.**

Если DNS обслуживаются у другого провайдера, записи редактируются у него. Не меняйте NS вслепую: это может затронуть почту. DNS обычно обновляется за несколько минут–сутки, иногда до 48 часов.

Если нужен и первоначально запрошенный адрес `cons.sgt-holding.ru`, администратор **старого домена** может настроить для него HTTPS-перенаправление на `https://cons.sgt-h.ru/ksk`. Для этого нужны доступ к DNS/хостингу `sgt-holding.ru` и сертификат для старого поддомена; новая покупка `sgt-h.ru` сама по себе не даёт управления старым доменом. Одной A/CNAME-записи для HTTP-перенаправления недостаточно. Основной пакет настроен на новый домен `sgt-h.ru` и `cons.sgt-h.ru`.

## 3. Включите бесплатный HTTPS

В панели хостинга откройте раздел SSL / сертификатов и выпустите бесплатный Let's Encrypt для:

- `sgt-h.ru`;
- `www.sgt-h.ru`;
- `cons.sgt-h.ru`.

Это может быть один сертификат с тремя именами или несколько сертификатов — согласно возможностям панели. Проверьте, что каждый сайт/псевдоним использует подходящий сертификат. Все имена должны уже указывать на хостинг. До загрузки нового сайта проверьте в браузере `https://sgt-h.ru`: не должно быть предупреждения о сертификате, даже если пока видна стандартная страница REG.RU. Платный SSL для этой схемы не требуется.

## 4. Выберите PHP и создайте базу

В настройках `sgt-h.ru` выберите **PHP 8.3 или новее**. Если `cons` создан как отдельный сайт с той же папкой, задайте ему ту же версию PHP. На установочной странице будет проверка расширений `pdo_mysql`, `fileinfo`, `mbstring`, `openssl`. Обычно они доступны на виртуальном хостинге; если проверка сообщает об отсутствии — включите модуль в панели или обратитесь в поддержку.

В разделе **Базы данных** создайте **новую пустую MySQL-базу** для сайта и отдельного пользователя с доступом к ней. Сохраните в менеджере паролей:

- сервер базы — точное имя из панели, часто `localhost`;
- полное имя базы, включая префикс, который добавит REG.RU;
- имя пользователя базы;
- пароль этого пользователя.

Не используйте базу другого работающего сайта. Ничего из существующей базы удалять не нужно. SQL-файлы вручную импортировать не потребуется: таблицы создаст установщик.

## 5. Загрузите готовый пакет

Скачайте [sgt-host0.zip](https://github.com/droptoptri/physics/raw/refs/heads/main/releases/sgt-host0.zip). Если GitHub открыл страницу файла, нажмите **Download raw file / Скачать исходный файл**.

Архив уже содержит собранный сайт и почтовую библиотеку. Запускать npm, Composer, Docker или терминал на вашем компьютере не нужно.

Внутри две рабочие папки:

```text
sgt-h.ru/       ← публичные файлы сайта, включая .htaccess и .user.ini
sgt-private/    ← закрытый backend; здесь позже появятся настройки и анкеты
```

Откройте файловый менеджер хостинга и перейдите **на один уровень выше корневой папки сайта sgt-h.ru**. В обычной структуре это папка `www`, в которой лежит папка домена. Загрузите ZIP туда и распакуйте. Должно получиться:

```text
www/
  sgt-h.ru/
    index.html
    assets/
    api/index.php
    admin.php
    setup.php
    .htaccess
    .user.ini
    ...
  sgt-private/
    bootstrap.php
    vendor/
    cron.php
    ...
```

Если панель использует другую структуру, скопируйте **содержимое** папки `sgt-h.ru` из архива в реальный корень сайта, а `sgt-private` разместите рядом с этим корнем. Например, рядом с `public_html`, если сайт обслуживается из него. Код находит закрытую папку именно на один уровень выше корня сайта.

Важно:

- Если в папке сайта уже есть файлы, сначала сделайте их резервную копию. Уберите стандартный `index.php` / `index.htm`, если он перекрывает новый `index.html`. Файлы других сайтов не трогайте.
- Покажите скрытые файлы в файловом менеджере: `.htaccess` и `.user.ini` должны попасть на сервер.
- **Не помещайте `sgt-private` внутрь папки сайта.** В ней будут пароли базы и закрытые анкеты.
- После распаковки удалите загруженный ZIP с сервера. Папки с исходниками проекта и `node_modules` загружать не нужно.
- У PHP должен быть доступ к чтению backend и записи в `sgt-private`; на типичном Хост-0 PHP запускается от владельца аккаунта. Для закрытой папки подходят права 700, для её конфиденциальных файлов — 600. Не устанавливайте 777. Если панель показывает ошибку прав, попросите поддержку проверить владельца файлов и доступ PHP к соседней папке.

## 6. Защитите первичную настройку

В `sgt-private` создайте текстовый файл **`install-password.txt`**. Впишите **только ваш уникальный установочный пароль длиной от 20 символов**, без пояснений. Удобно сгенерировать его в менеджере паролей. Шаблон `install-password.example.txt` объясняет формат; просто переименовать шаблон без замены текста недостаточно.

Этот пароль нужен однократно, чтобы посторонний человек не смог первым подключить базу и создать администратора. Файл находится за пределами публичного сайта и автоматически удалится после успешной установки.

## 7. Пройдите установку в браузере

Откройте **https://sgt-h.ru/setup**.

1. Убедитесь, что все пункты проверки хостинга помечены «Готово».
2. Введите ваш установочный пароль.
3. Заполните сервер базы, имя базы, пользователя и пароль из шага 4.
4. Укажите свой email администратора и **новый отдельный пароль от 12 символов**. Это доступ к управлению сайтом, он не обязан совпадать с паролем REG.RU или почты.
5. Подтвердите создание служебной учётной записи и нажмите **Завершить установку**.

После сообщения «Сайт настроен» откройте **https://sgt-h.ru/admin** и войдите с только что заданными данными. Общего пароля по умолчанию нет. Повторная установка блокируется автоматически.

Сайт уже может регистрировать партнёров, хранить анкеты и показывать предложения подтверждённым компаниям. Для доставки писем выполните следующий шаг.

## 8. Подключите почту

Для личных `ak@sgt-h.ru`, `ok@sgt-h.ru` и общего `ksk@sgt-h.ru` подготовлена [отдельная инструкция почты и Gmail](MAIL.md). Подтверждено подключение `ak` к `antnpk@gmail.com`; настройка доступа Олега отложена. Ящики создаются в разделе **Почта** ISPmanager; поле «E-Mail администратора сайта» их не создаёт.


В `/admin` откройте **Почта → Настроить SMTP**. Укажите параметры своего почтового провайдера:

- имя SMTP-сервера;
- порт **465 (TLS)** либо **587 (STARTTLS)**;
- логин;
- email отправителя, который разрешён провайдером;
- пароль приложения / SMTP-пароль.

Получатель фиксирован: **antnpk@gmail.com**. Отправитель может отличаться от получателя. Настройки сохраняются в закрытой папке; пароль обратно в интерфейсе не показывается.

Если используете Gmail, параметры обычно такие: `smtp.gmail.com`, порт 465, логин — ваш Gmail-адрес, отправитель — тот же разрешённый Gmail-адрес, пароль — **пароль приложения Google**, если он доступен для вашей учётной записи. Не вставляйте обычный пароль почты вместо пароля приложения. Для отправителя на своём домене настройте SPF/DKIM по инструкции именно вашего почтового сервиса.

Сохраните настройки. Отправьте одну тестовую анкету через сайт, затем в админке нажмите **Отправить очередь**. Убедитесь, что письмо с вложением пришло на `antnpk@gmail.com`, проверьте «Спам». Статус «Отправлено» означает, что SMTP-сервер принял письмо; попадание во «Входящие» проверяется отдельно.

Без SMTP сайт сохраняет заявки в закрытой очереди и честно сообщает, что почта ещё не подключена. Внешняя доставка не может считаться проверенной до теста на вашем хостинге.

## 9. Включите автоматическую отправку

В панели хостинга найдите **Планировщик / Cron**. Добавьте задачу **каждую минуту**:

```sh
/opt/php/8.3/bin/php /ПОЛНЫЙ_ПУТЬ/sgt-private/cron.php
```

Замените `/ПОЛНЫЙ_ПУТЬ/sgt-private/cron.php` полным путём к файлу `cron.php`, который показывает файловый менеджер. Если выбрали PHP 8.4, используйте `/opt/php/8.4/bin/php` соответственно. Сам скрипт запускается только из командной строки; открывать его по веб-адресу не нужно.

Поля расписания: минута `*`, час `*`, день месяца `*`, месяц `*`, день недели `*`. В панели с готовым выбором интервала выберите «Каждую минуту». Если тариф ограничивает частоту задач, используйте минимальный разрешённый интервал; письма будут уходить с соответствующей задержкой.

Задача обрабатывает до пяти писем за запуск, защищена от одновременного выполнения и повторяет неудачную доставку с увеличением интервала. До настройки cron почту можно отправлять кнопкой в админке, но автоматической доставки без cron не будет.

Если не удаётся найти поле пути или расписание, отправьте поддержке этот запрос:

> Для сайта sgt-h.ru на Хост-0 нужно запустить каждую минуту файл sgt-private/cron.php через PHP 8.3+. Папка sgt-private находится рядом с корневой папкой сайта, за пределами публичного каталога. Пожалуйста, проверьте полный путь, CLI-версию PHP, доступность SMTP 465/587 и настройте cron.

## 10. Проверьте сайт перед приглашением партнёров

1. Откройте сайт на телефоне. Проверьте меню, КСК, ГЕО, пробелы и переносы. Баннер тестовой версии на своём домене отсутствует.
2. Откройте `https://cons.sgt-h.ru`: должен сразу открыться СГТ-КСК. Кабинет доступен по `/cabinet`.
3. Скачайте опросный лист и отправьте согласованную тестовую анкету без лишних персональных данных.
4. В `/admin` проверьте её наличие и скачивание. По адресу `https://sgt-h.ru/sgt-private/config.json` доступ должен быть закрыт (403 или 404).
5. Убедитесь, что почта с вложением действительно пришла на `antnpk@gmail.com`, в том числе без нажатия кнопки после настройки cron.
6. Зарегистрируйте тестового партнёра: он должен видеть ожидание проверки, а не предложения.
7. В `/admin` подтвердите его, добавьте реальное предложение и проверьте доступ после обновления кабинета. Отзовите доступ — закрытые предложения должны стать недоступны.
8. Уточните юридическое наименование и реквизиты оператора, сроки хранения и текст `/privacy` с ответственным сотрудником до сбора реальных анкет. Полного набора реквизитов компании пока нет; он не выдумывался.

Основной домен и `cons` используют отдельные служебные cookie: на втором адресе партнёру может потребоваться войти ещё раз. Администрирование удобно вести на основном `sgt-h.ru`.

## Управление, резервные копии и обновления

В **https://sgt-h.ru/admin** доступны:

- подтверждение и отзыв доступа партнёров;
- смена пароля партнёра или удаление его аккаунта;
- публикация и закрытие тендеров;
- просмотр и скачивание закрытых анкет, удаление заявки вместе с файлом;
- настройка SMTP и ручная отправка очереди;
- смена вашего пароля администратора.

Панель показывает последние 200 партнёров, тендеров и анкет. Просроченные/закрытые предложения не выдаются партнёрам. Удаление аккаунта и удаление его ранее отправленной анкеты — отдельные действия. Копии писем и вложений в почтовом ящике удаляются отдельно.

Для резервной копии используйте инструменты REG.RU: **экспорт MySQL-базы и копию всей `sgt-private`, включая config.json, secret.key и uploads**. Храните копии в защищённом отдельном месте. На время согласованного копирования попросите администратора временно остановить приём заявок и cron. Пароли, анкеты и резервные копии не публикуйте в GitHub и не оставляйте в папке сайта.

При обновлении сначала сделайте копию базы и закрытой папки. Затем замените публичные файлы новой сборкой и обновите программные файлы backend. **Сохраняйте существующие `config.json`, `secret.key`, `uploads` и базу.** Не заменяйте закрытую папку пустой папкой из архива целиком и не запускайте повторную установку. Если версия требует изменения схемы базы, выполняйте только инструкцию конкретного обновления.

Если потеряли пароль единственного администратора, не удаляйте базу и `config.json`: администратор хостинга может изменить хеш пароля через закрытый служебный скрипт, предварительно подтвердив доступ к аккаунту. Пароли в открытых SQL-запросах и общедоступные восстановительные страницы использовать не нужно.

## Если что-то не открывается

| Симптом | Что проверить |
| --- | --- |
| Стандартная страница REG.RU | Корень WWW-домена, наличие `index.html`, старые индексные файлы, DNS и кеш браузера |
| `/setup` или `/cabinet` даёт 404 | Загружен ли скрытый `.htaccess`, включена ли его обработка Apache, правильная ли корневая папка |
| Ошибка 500 | Версия PHP 8.3+, расположение соседней `sgt-private`, права владельца; журнал ошибок хостинга |
| Не удаётся подключить базу | Полные имена с префиксом, сервер, пароль, доступ пользователя именно к этой базе |
| Сертификат не подходит для `cons` | DNS и псевдоним/WWW-домен `cons`, список имён сертификата |
| Заявка есть, письма нет | SMTP-параметры, пароль приложения, cron, статус очереди, спам и блокировка исходящего порта |
| Цикл перенаправлений HTTPS | Передаёт ли фронтенд хостинга признак HTTPS в Apache/PHP; попросите поддержку проверить прокси-настройку |

Никому не отправляйте файл `config.json`, `secret.key`, пароль установки или полный архив закрытой папки для «диагностики». Для помощи обычно достаточно названия ошибки и обезличенной строки журнала.

Официальная справка REG.RU: [настройка DNS](https://help.reg.ru/support/dns/nastroika-zony/), [размещение сайта](https://help.reg.ru/support/hosting-i-servery/kak-razmestit-sayt-na-hostinge/), [выбор версии PHP](https://help.reg.ru/support/hosting/php-asp-net-i-skripty/kak-smenit-versiyu-php-na-hostinge), [PHP в командной строке](https://help.reg.ru/support/hosting/php-asp-net-i-skripty/rabota-s-php-skriptami-v-komandnoy-stroke).

Для альтернативного размещения на отдельном VPS сохранена [инструкция Node.js/Docker](VPS.md). Для выбранного вами Хост-0 она не требуется.

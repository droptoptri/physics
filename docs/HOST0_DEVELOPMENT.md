# Проверка и пересборка версии Хост-0

Пользователь устанавливает готовый `releases/sgt-host0.zip` через файловый менеджер; инструменты ниже нужны только разработчику и CI.

Требования: Node.js 24+, npm, Python 3 (упаковка ZIP), Docker/Compose, OpenSSL, Chromium для Playwright. В `hosting/php` — Composer-проект с зафиксированным PHPMailer. Секретов и преднастроенных аккаунтов в архиве нет.

Из корня репозитория:

```sh
npm ci
# Можно использовать локальный Composer 2 с PHP 8.3+ либо контейнер:
docker run --rm --user "$(id -u):$(id -g)" \
  -e COMPOSER_HOME=/tmp/composer \
  -v "$PWD/hosting/php:/app" -w /app \
  composer:2 composer install --no-dev --prefer-dist --no-interaction --no-progress
npm run build:host0
docker build -t sgt-host0-test:local -f hosting/php/tests/Dockerfile .host0-build
npm run test:host0
```

В облачной среде с защищённым исходящим прокси сохраните проверку TLS: передайте Composer доверенный CA как read-only mount и укажите `COMPOSER_CAFILE` на этот файл. Не отключайте проверку сертификатов. Для Docker CLI в среде с read-only домашней папкой задайте `DOCKER_CONFIG=/tmp/sgt-docker-config`. Docker-образы и живые процессы могут не переживать перезапуск облачной среды.

`prepare-host0.mjs` собирает архив из явного списка backend-файлов, текущего `dist`, установленных vendor-зависимостей и инструкции. Рабочая папка `.host0-build` игнорируется Git. Конфигурация, ключ установки, секрет сессий, базы и загруженные анкеты никогда не копируются в архив.

`test-host0.mjs` использует изолированные контейнеры Apache/PHP 8.3 и MariaDB 11, отдельную Docker-сеть, временную базу и закрытый том. Проверяется реальный `.htaccess`, а не упрощённый маршрутизатор PHP development server. Порт 3105 должен быть свободен. Скрипт создаёт уникальные тестовые пароли и удаляет только собственные контейнеры/тома в finally. Не запускайте его с данными реального хостинга.

Почтовая проверка использует локальный TLS-приёмник с временным CA. PHP доверяет только этому тестовому сертификату через отдельный тестовый ini. Приёмник не пересылает письма наружу; проверяются адрес `antnpk@gmail.com`, вложение, отказ SMTP и успешная повторная отправка. Проверка не подтверждает доставку в Gmail с реального хостинга.

Есть отдельные браузерные проверки девяти ширин экрана, обоих способов сборки и доступности:

```sh
npm test
npm run build
npm run test:e2e
npm run build:pages
npm run test:pages
```

Не меняйте `.env.production` или настоящую базу для запуска тестов. Они не нужны для PHP-проверок. Публичные GitHub Pages обновляются только из `sgt-design-preview`; основной исходный код и установочный архив находятся в `main`.

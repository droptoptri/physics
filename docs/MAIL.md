# Почта sgt-h.ru: ak, ok и общий ksk

Согласованная схема для уже купленного Хост-0:

| Адрес | Назначение | Получение писем / доступ |
| --- | --- | --- |
| **ak@sgt-h.ru** | Личная почта владельца | Копии в **antnpk@gmail.com**, отправка из Gmail через SMTP REG.RU |
| **ok@sgt-h.ru** | Личная почта Олега | Создать отдельный ящик; подключение Олега и передача ему доступа отложены по указанию владельца |
| **ksk@sgt-h.ru** | Общая почта консорциума | Самостоятельный ящик с архивом; владельцу — доступ через webmail/IMAP и копии в Gmail; Олегу — позже |

**Статус: подготовлена инструкция, а не подтверждение создания ящиков.** В этой сессии нет инструмента управления аккаунтом REG.RU или Gmail. Создание, проверка DNS, включение пересылки и подтверждение Gmail выполняются в этих аккаунтах. Пароли и коды не нужно отправлять в чат или GitHub.

## 1. Создать три самостоятельных ящика

На присланном скриншоте открыты настройки **сайта**. Поле «E-Mail администратора» не создаёт почтовый ящик.

1. В ISPmanager откройте **Почта** слева.
2. Проверьте наличие почтового домена `sgt-h.ru`. Если его нет, добавьте в разделе почтовых доменов этой же услуги.
3. Нажмите **Создать ящик / Создать**. В поле имени до `@` введите `ak`, выберите домен `sgt-h.ru` и сгенерируйте отдельный длинный пароль.
4. Повторите для `ok` и `ksk`. Это три разных ящика, не псевдонимы одного адреса.
5. Сохраните пароли в менеджере паролей. Для `ok` передача пароля Олегу пока не выполняется.
6. Проверьте вход в `ak` и `ksk` через кнопку входа в почту самой панели. Логин — **полный адрес** ящика. Веб-интерфейс берите из панели, а не из случайной ссылки.

Не выдавайте Олегу пароль всего хостинга ради доступа к почте. Личный `ak` не требует доступа Олега; общим будет только `ksk`.

## 2. Проверить почтовые DNS-записи

Для почты виртуального Linux-хостинга REG.RU в официальной инструкции указаны:

| Имя | Тип | Значение | Приоритет |
| --- | --- | --- | --- |
| `@` | MX | `mx1.hosting.reg.ru.` | 10 |
| `@` | MX | `mx2.hosting.reg.ru.` | 15 |

Если используются DNS `ns1.hosting.reg.ru` и `ns2.hosting.reg.ru`, необходимые записи могут создаваться автоматически. Проверьте их перед ручным добавлением. Если используются другие DNS, записи нужно добавить там, где обслуживается зона `sgt-h.ru`.

SPF должен разрешать отправку через хостинг REG.RU. Предпочтительно использовать запись, показанную самой панелью. Шаблон из документации провайдера с IPv4 **31.31.196.9 из вашего скриншота**:

```text
v=spf1 a mx include:_spf.hosting.reg.ru ip4:31.31.196.9 ~all
```

Перед применением сверьте IP с текущей карточкой хостинга. Если SPF уже существует, его нужно объединить с настройками действующих отправителей, а не создавать второй `v=spf1`. Не удаляйте почтовые записи другого действующего сервиса без плана переноса.

Включите **DKIM** в настройках почтового домена и используйте TXT-запись, которую выдаст панель. Селектор и ключ не выдумываются. Для DMARC используйте настройки провайдера с учётом существующей политики домена; действующую строгую политику не нужно ослаблять автоматически.

Проверка MX/SPF/DKIM на вашем домене из этой среды не выполнена: DNS-резолвер вернул ошибку соединения. Таблица выше — конфигурация из документации REG.RU, а не результат чтения вашей DNS-зоны.

## 3. Входящие ak → Gmail

В ISPmanager откройте **Почта → ak@sgt-h.ru → Изменить**:

- поле **«Слать копии писем на e-mail»**: `antnpk@gmail.com`;
- **«Не сохранять в ящик» — оставить выключенным**.

Если панель показывает отдельную вкладку «Перенаправление», укажите там тот же адрес и сохранение локальной копии. Названия полей зависят от версии панели.

Так входящие письма появляются в Gmail, а исходный ящик сохраняет архив на REG.RU. Письма, прочитанные в Gmail, не обязательно получат отметку «прочитано» в ящике REG.RU: пересылка создаёт копии, а не синхронизацию папок. Gmail-подключение здесь строится на пересылке, без забора писем через POP.

## 4. Отправка из Gmail как ak@sgt-h.ru

В браузерном Gmail аккаунта **antnpk@gmail.com**:

1. Нажмите шестерёнку → **Все настройки → Аккаунты и импорт**. В некоторых интерфейсах вкладка называется «Аккаунты».
2. В блоке **«Отправлять письма как»** нажмите **«Добавить другой адрес электронной почты»**.
3. Укажите ваше имя и `ak@sgt-h.ru`. Для своего личного адреса стандартный вариант «Использовать как псевдоним» подходит.
4. Введите настройки из официальной инструкции REG.RU:

   | Поле | Значение |
   | --- | --- |
   | SMTP-сервер | **mail.hosting.reg.ru** |
   | Порт | **465** |
   | Защита | **SSL / SSL-TLS** |
   | Имя пользователя | **ak@sgt-h.ru** |
   | Пароль | Пароль **ящика ak**, не аккаунта REG.RU и не Gmail |

5. Подтвердите адрес письмом, которое Google отправит на `ak@sgt-h.ru`. При уже работающей пересылке оно должно появиться в `antnpk@gmail.com`; его также можно открыть в webmail REG.RU.
6. В настройках ответов выберите **«Отвечать с адреса, на который отправлено письмо»**, если хотите сохранять корпоративный адрес при ответах.
7. При создании письма проверьте поле **«От кого»**: в нём должен быть выбран `ak@sgt-h.ru`. Делать его адресом по умолчанию следует только если вы хотите использовать его и для обычной переписки Gmail.

Пароль ящика вводится только в защищённом окне Gmail. Не отключайте проверку TLS при ошибке подключения.

Получение и отправка — два отдельных шага. Одна пересылка не даёт Gmail права отправлять от имени корпоративного адреса.

## 5. Общий ksk@sgt-h.ru

- Создайте именно **отдельный ящик** `ksk`, чтобы у команды был самостоятельный архив и пароль.
- Сейчас владельцу можно настроить копии на `antnpk@gmail.com`, сохраняя письма в `ksk`. Не добавляйте одновременно `ak` и его Gmail-получателя: это создаст дубли.
- Полный доступ к общему архиву — через webmail либо IMAP. Для IMAP используйте **mail.hosting.reg.ru**, порт **993**, **SSL/TLS**, логин **ksk@sgt-h.ru** и пароль этого ящика. Отправка — SMTP **mail.hosting.reg.ru:465**, SSL/TLS, тот же полный логин.
- Пароль общего ящика храните в менеджере паролей. Если почтовая услуга предоставляет индивидуальные делегированные права, используйте их. Если нет, доступ к самостоятельному общему ящику можно передать через защищённое совместное хранилище паролей; пароль хостинга для этого не нужен.
- **Олега сейчас не подключаем.** Позже определим его способ входа, передадим доступ к `ok` и `ksk` и при необходимости добавим копии писем `ksk` на `ok@sgt-h.ru`.

Если понадобится отвечать из Gmail и от имени `ksk`, добавьте в Gmail второй адрес через «Отправлять письма как», используя **логин и пароль ksk**. Одна настройка для `ak` не распространяется на `ksk`. При такой отправке исходящие могут храниться только в Gmail; для единой командной папки «Отправленные» используйте IMAP-клиент/webmail с сохранением писем на сервере.

## 6. Отправитель уведомлений сайта

После создания и проверки `ksk` в панели сайта `/admin → Почта → Настроить SMTP` можно задать:

| Поле | Значение |
| --- | --- |
| SMTP-сервер | `mail.hosting.reg.ru` |
| Порт | `465` |
| Логин | `ksk@sgt-h.ru` |
| Email отправителя | `ksk@sgt-h.ru` |
| Пароль | Пароль ящика `ksk` |

Здесь сохраняется ранее заданный получатель анкет **antnpk@gmail.com**. Отправка уведомления сайта и входящая пересылка общего ящика — разные операции. Если позднее потребуется доставлять анкеты также Олегу, маршрут согласуется после уточнения его доступа.

## 7. Проверить работу перед использованием

1. С другого почтового адреса отправьте тестовое письмо на `ak@sgt-h.ru`: проверьте его в webmail и Gmail.
2. Ответьте из Gmail с выбранным `ak@sgt-h.ru`: получатель должен видеть этот адрес. В Gmail «Показать оригинал» проверьте результаты SPF/DKIM/DMARC.
3. Аналогично проверьте входящие `ksk` и копию владельцу. В письме не должно быть повторной циклической пересылки.
4. Отправьте тест на `ok`, проверьте его наличие через панель, но не подключайте чужие адреса и не отправляйте Олегу пароли до отдельного шага.
5. После настройки SMTP сайта отправьте тестовую анкету и проверьте получение вложения на `antnpk@gmail.com`.

Пока проверки в самих аккаунтах не выполнены, ящики, пересылка и Gmail-подтверждение не считаются настроенными.

# СГТ-Холдинг

Новый сайт компании: СГТ-КСК, СГТ-ГЕО, анкета партнёра и закрытые предложения по тендерам.

React 19 + TypeScript + Vite, Express 5, встроенный SQLite Node.js 24. Шрифты, графика и документы обслуживаются локально. Внешних трекеров нет.

## Тестирование в браузере

[Открыть интерактивную версию GitHub Pages](https://droptoptri.github.io/physics/)

На Pages работают анимации, навигация, раскрытие направлений, скачивание документов, локальная проверка формы и демонстрационный кабинет с поиском и фильтрами. Баннер помечает тестовый режим. Данные, файлы и пароли не отправляются; демо-предложения вымышлены. Реальная регистрация, закрытые тендеры и почтовая очередь работают только в серверной версии.

[Запустить полную серверную версию через GitHub Codespaces](https://codespaces.new/droptoptri/physics?ref=main&quickstart=1)

GitHub предложит создать Codespace. Конфигурация автоматически устанавливает Node.js 24 и зависимости, запускает приложение и открывает порт 3000. Порт по умолчанию приватный. Создание Codespace из текущей среды не выполнялось; для серверной разработки также подходит обычный хостинг Node.js 24.

## Запуск

```sh
cd /workspace/physics
npm ci --cache /tmp/sgt-npm-cache
npm run dev
```

Сервер приложения слушает порт 3000. Фронтенд и API работают на одном порту. `/` — лендинг, `/ksk` — вход в раздел консорциума, `/geo` — вход в раздел ГЕО, `/cabinet` — кабинет партнёра, `/privacy` — обработка данных. Это существующий изолированный checkout; создавать дополнительные worktree не нужно.

Локальная разработка не требует внешних сервисов. Для почтовой доставки настройте SMTP. До настройки анкеты **сохраняются в очереди, но письма не отправляются**; интерфейс сообщает об этом.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
```

Браузерные проверки покрывают мобильную и настольную версии, форму, регистрацию, доступ к предложениям, поиск и автоматические WCAG A/AA проверки. Они используют установленный `/usr/bin/chromium`. На другой машине задайте `CHROMIUM_PATH` либо установите совместимый браузер командой `npx playwright install chromium`. E2E запускает отдельный сервер на порту 3101; данные проверок находятся в `/tmp/sgt-playwright-data`, не в рабочей базе.

## Данные и доступ

- База `var/sgt.sqlite` и вложения `var/uploads` находятся вне публичной части и игнорируются Git. В production задайте абсолютный `DATA_DIR` на постоянном диске вне checkout.
- Пароли защищены scrypt с отдельной случайной солью. Сессии — HttpOnly cookie; в базе хранится хеш токена. В production cookie требует HTTPS.
- После регистрации аккаунт ожидает ручного подтверждения. Сервер проверяет подтверждение при каждом запросе тендеров. Общедоступных тестовых аккаунтов и фиктивных тендеров нет.
- Формы защищены CSRF, проверкой Origin и ограничением частоты запросов. Вложения DOCX/PDF проверяются по содержимому, максимум 10 МБ. Имена файлов заменяются случайными. Вложения доступны только администратору на сервере и в письме.
- Письма адресованы только `antnpk@gmail.com`. SMTP не отключает проверку TLS. Сбой доставки сохраняет заявку в очереди с повторными попытками. Подробности и команды — в [инструкции администратора](docs/DEPLOYMENT.md).

## Содержание и текущие ограничения

[Редакционная справка](docs/CONTENT.md) фиксирует источники и редакционные решения. КСК собран по предоставленной справке; ГЕО и общие контакты переработаны по сохранённой HTML-копии действующего сайта, полученной от пользователя. Прямой доступ к старому сайту по-прежнему ограничен сетевой политикой, но для переноса содержания это больше не является препятствием.

Рабочая версия создана локально. Основной сайт компании и DNS не изменялись. Для GitHub Pages подготовлена отдельная тестовая сборка. Перед публичным запуском необходимы сервер, TLS, постоянный диск, реквизиты оператора для политики обработки данных и подключение почты. Отправка в реальный почтовый ящик не проверялась без SMTP-доступа.

## Сборка и публикация Pages

`npm run build:pages` создаёт `dist-pages` с базовым путём `/physics/` и отдельными входами `/geo/`, `/ksk/`, `/cabinet/`, `/privacy/`. `npm run test:pages` проверяет такую сборку на настольном и мобильном экране. Обычная `npm run build` создаёт полную серверную сборку без тестового режима.

Workflow `.github/workflows/ci.yml` на push в `main` проверяет сервер, обе сборки и браузерные сценарии, затем публикует проверенный артефакт через GitHub Pages. В pull request выполняются только проверки.
